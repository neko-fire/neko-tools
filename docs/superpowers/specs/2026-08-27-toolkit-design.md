# Toolkit single-pager design

## Goal

Ship a simple dark-mode utility page with a browser deployment and a macOS Electron wrapper. Version one contains a UTC timestamp converter and a UUIDv7 generator. Python owns all conversion and ID generation so the browser and desktop experiences share the same behaviour.

## Architecture

- **Backend:** a small FastAPI application, started locally for both the browser and Electron. It exposes JSON endpoints and serves the static UI.
- **Frontend:** framework-free HTML, CSS, and JavaScript. It calls the Python API; no client-side UUID generation or date-conversion source of truth.
- **macOS shell:** Electron starts the bundled Python server, waits for it to be ready, and loads the local page in a native-feeling app window.
- **Packaging:** project scripts run the web app in development and package the Electron shell for macOS.

The structure stays feature-oriented: every future tool gets a backend route module, a frontend panel module, and a short manifest entry. Shared UI primitives (copy button, status feedback, panel transitions) stay in small common files. This gives future tools clear boundaries without a plugin framework.

## Version-one features

### UTC timestamp converter

- Accept date/time strings and Unix timestamps.
- Identify Unix seconds and milliseconds.
- Convert in both directions: date/time to timestamp and timestamp to date/time.
- Return UTC ISO 8601, local date/time, Unix seconds, Unix milliseconds, and relative time.
- Provide visible error guidance for invalid values and individual copy actions for output values.

### UUIDv7 generator

- Generate one or a selected quantity of UUIDv7 values using Python's `uuid7` package.
- Display the session-only list in generation order.
- Copy an individual ID or the complete list, and clear the list.
- Do not persist IDs after a reload or app restart.

## Interaction and visual design

- One responsive page with a compact top bar and two primary tool panels. Desktop places them side by side; narrow screens stack them.
- Dark, warm near-black backgrounds; subtle elevated surfaces; one blue primary accent; system typography; monospaced figures and IDs.
- Every control has a visible label, keyboard focus state, appropriate touch target, and text feedback beyond colour alone.
- Transitions use opacity and transforms only: typically 160–220 ms for panel entrance, copied feedback, and replacement results. They never block input or shift layout, and are disabled for `prefers-reduced-motion`.
- Electron uses ordinary macOS window controls and opens at a useful desktop size. The app does not mimic native chrome inside its content area.

## API contract

- `POST /api/convert`: accepts a single input string and an optional local time-zone context; returns normalized conversion fields or a descriptive validation error.
- `POST /api/uuids`: accepts a positive generation count and returns UUIDv7 values generated by Python.

All browser-facing logic treats Python responses as authoritative. Input validation is duplicated client-side only when it improves immediate usability; the backend remains the final validator.

## Error handling and testing

- The API returns structured errors with a recovery-focused message; the matching field displays it accessibly.
- Electron shows a concise startup failure screen if its Python service cannot launch.
- Automated Python tests cover timestamp units, accepted date inputs, time-zone conversion, invalid input, UUIDv7 shape/order, and batch-size validation.
- A lightweight browser smoke check verifies both panels can submit, render results, copy values, and clear the UUID session list.

## Out of scope

- Persistence, user accounts, synchronization, analytics, and remote services.
- Client-side UUID or conversion implementations.
- A generic extension/plugin runtime; feature modules and a manifest are sufficient for now.
